## 1. Project Overview & Non-Goals

### Vision

Uniplan UQ es un panel académico personal para **un solo estudiante** de Ingeniería de Sistemas y
Computación (jornada nocturna) de la Universidad del Quindío. En una pestaña del navegador muestra
todas las tareas y parciales con sus fechas, las notas por materia, el pensum completo con
prerrequisitos y avance de carrera, y recomienda qué materias matricular el próximo semestre.

Los datos entran solos desde dos fuentes que el estudiante ya usa: el SAC de la universidad
(`https://sac.uniquindio.edu.co/sgacampus/`, una aplicación Academusoft/SINU sin API y con sesión
de 15 minutos) y Google Classroom con la cuenta institucional. Y **todo es editable a mano**,
porque las fechas que se acuerdan en clase cambian sin dejar registro: lo que el estudiante corrige
nunca vuelve a ser pisado por una sincronización.

### Users

| Persona | What they come to do | Frequency |
|---|---|---|
| El estudiante (único usuario, en su propio equipo, Brave sobre Windows 11) | Ver qué vence, registrar y corregir fechas y notas, revisar su avance y decidir qué matricular | Diaria durante el semestre; la ruta de matrícula, una vez por semestre |

### Goals — v1 scope

1. Agenda de tareas, parciales, quices y proyectos agrupada por urgencia y en calendario mensual,
   con alta rápida, edición en línea, filtros y marca de "hecha".
2. Notas por materia con promedio ponderado o simple, porcentaje que falta por calificar y nota
   necesaria para aprobar.
3. Pensum completo en cuadrícula por año y semestre, con estados, prerrequisitos resaltados,
   edición de cada materia y barra de avance.
4. Recomendación determinista (sin IA) de materias para el próximo semestre, con el motivo de cada una.
5. Importación de solo lectura desde las páginas del SAC que el estudiante tiene abiertas.
6. Sincronización opcional de solo lectura con Google Classroom.
7. Recordatorios del navegador antes de cada vencimiento.
8. Respaldo y restauración de todos los datos en un archivo JSON, con registro de sincronizaciones.

### Non-Goals — explicitly out of scope for v1

| Not building | Why not now | Revisit when |
|---|---|---|
| App móvil o vista alojada en la web | Exige un servidor o una tienda; el uso diario es en el computador | El estudiante pida consultar desde el celular: v2 será una vista de solo lectura del archivo de respaldo |
| Sincronización desatendida o en segundo plano del SAC | La sesión del SAC dura 15 minutos y su inicio de sesión es anti-automatización por diseño | La universidad publique una API |
| Automatizar el inicio de sesión o guardar credenciales | Riesgo de seguridad y de bloqueo de la cuenta institucional | Nunca |
| Escribir cualquier cosa en el SAC (matricular, enviar formularios) | Un error ahí tiene consecuencias académicas reales | Nunca |
| Leer fechas dentro de los PDF de actas de concertación | Formato libre por profesor; un lector de PDF fiable es un proyecto aparte | Las actas lleguen en un formato estable |
| Funciones con IA o modelos de lenguaje | La recomendación debe ser explicable y funcionar sin red | Exista una necesidad que una regla determinista no cubra |
| Publicación en Chrome Web Store, Firefox o Safari | Es una herramienta de un solo usuario cargada sin empaquetar | Un segundo usuario la pida |
| Multiusuario o cuentas propias | No hay segundo usuario ni servidor | Lo mismo que la fila anterior |
| Optimizar cruces de horario en la recomendación | Los horarios del próximo semestre no existen cuando se decide | El SAC exponga la oferta de horarios antes de la matrícula |
| Tema claro | El diseño decidido es oscuro y minimalista | El estudiante lo pida |

**El constructor no implementa nada de esta tabla**, ni siquiera como un añadido pequeño mientras
trabaja en un paso vecino. Si un paso parece exigir un no-objetivo, es un defecto del blueprint:
se detiene y se reporta.

### Success metrics

| Metric | Target | How measured |
|---|---|---|
| Compuerta global | Todos los comandos de §20.1 salen con 0 al terminar el paso 16 | Ejecutar el bloque de §20.1 |
| Ediciones preservadas | 0 campos editados por el estudiante pisados por una sincronización | `pnpm test tests/sync/merge.test.ts` y `pnpm e2e e2e/full-flow.spec.ts` |
| Datos al día | Al menos una importación del SAC con estado `ok` o `partial` por semana durante el semestre | Sección "Registro de sincronización" de Ajustes (tabla `syncRuns`) |
| Respaldo vigente | Último respaldo con menos de 7 días | Aviso "Último respaldo" de Ajustes (`settings.lastBackupAt`) |

## 2. Tech Stack

**Runtime track: ts-node.** Esta tabla nombra *decisiones*, no versiones. Cada versión vive en §11
y en ningún otro lugar de la prosa.

Las versiones vienen del informe de `stack-researcher` de esta sesión, que es la autoridad;
`knowledge/runtime-tracks/ts-node.md` no se usó para ninguna versión porque el informe resolvió
todas.

| Layer | Choice | Why this, over what |
|---|---|---|
| Language / runtime | TypeScript sobre Node.js (solo para construir y probar) | La plataforma de extensiones solo ejecuta JavaScript; TypeScript estricto atrapa en compilación los errores de datos nulos. Se descartó la línea mayor siguiente del compilador porque no tiene API estable |
| Framework | WXT (Manifest V3) | Genera el manifiesto, tipa las rutas de los entrypoints y produce un build estático cargable. Se descartó un manifiesto JSON a mano con Vite puro: más piezas que mantener para el mismo resultado |
| Styling | Tailwind con tokens `@theme` | Los tokens del diseño quedan en un solo archivo CSS y cada componente los referencia por nombre. Se descartó CSS-in-JS: genera estilos en tiempo de ejecución, incómodo bajo la CSP de extensiones |
| Component layer | Componentes propios en React, iconos de `lucide-react` | Cinco vistas pequeñas no justifican una librería de componentes; menos dependencias que auditar |
| Database | IndexedDB del perfil del navegador | Único almacenamiento local con capacidad y consultas suficientes. `storage.local` se descartó: sin índices y con valores serializados enteros |
| ORM / data access | Dexie + `dexie-react-hooks` | Versionado de esquema, transacciones y `useLiveQuery` reactivo. Se descartó la API cruda de IndexedDB por verbosa y propensa a errores |
| Auth | NOT APPLICABLE | Sin cuentas propias. El token de solo lectura de Classroom se obtiene con `launchWebAuthFlow` y se describe en §5 y §14 |
| Background work | Service worker MV3 con `alarms` | Los temporizadores mueren con el worker; las alarmas lo despiertan |
| Payments | NOT APPLICABLE | Herramienta personal gratuita |
| File storage | NOT APPLICABLE | Solo se guardan enlaces; los adjuntos siguen en Classroom o Drive |
| Email / notifications | `browser.notifications` | Aviso local del sistema sin servidor ni correo |
| Hosting | NOT APPLICABLE — extensión personal cargada sin empaquetar; sin servidor | Ver §12 |
| Package manager | pnpm | El del equipo del estudiante, verificado con esta misma lista de dependencias |
| Validation | zod | Una sola definición da el tipo y la validación en cada borde |
| Tests | Vitest + happy-dom + fake-indexeddb; Playwright | Lógica pura rápida en Node y comportamiento real contra el build cargado en Chromium |
| Lint / format | Biome | Una herramienta y una configuración para formato y lint |

### Compatibility check

Revisado contra `knowledge/stack-compatibility.md`. Una fila aplica: *plataforma de extensiones +
canal de desarrollo que emite `eval` o código remoto* — la CSP de extensiones rechaza los builds
de desarrollo con HMR aunque el build de producción pase. Este blueprint lo evita así: **todas las
compuertas corren contra el build estático** (`pnpm build`, y Playwright carga
`.output/chrome-mv3`); `pnpm dev` existe solo para iterar a mano y ninguna verificación lo usa.
No hay ninguna otra combinación conocida como mala en este stack.

## 4. Data Model

Base Dexie llamada `uniplan`, una sola por perfil del navegador. Los tipos se infieren de los
esquemas zod de `src/domain/schemas.ts`, cuyo cuerpo literal está en el paso 2 de §9.

**syncRuns** — una corrida de sincronización: `id`, `source` (`sac` \| `classroom`), `startedAt`,
`finishedAt`, `status` (`ok` \| `partial` \| `error`), `counts`
(`{ created, updated, skipped, unmatched }`), `error` (string \| null).

**notified** — `key` = `<itemId>|<leadHours>`; evita repetir un recordatorio.

### Relationships

- `subjects —(1:N)→ items` por `items.subjectId`. Borrar una materia no borra sus ítems: quedan
  con `subjectId` intacto y se muestran como "Sin materia". En v1 la interfaz no borra materias.
- `subjects —(1:N)→ grades` por `grades.subjectId`. Misma regla.
- `subjects —(1:N)→ scheduleBlocks` por `scheduleBlocks.subjectId`.
- `subjects —(N:M)→ subjects` por `prereqIds`. Sin cascada; un cambio que crearía un ciclo se rechaza.
- `items —(1:N)→ notified` por el prefijo de `key`. Sin cascada; las claves huérfanas son inocuas.

No hay cascadas de borrado en ninguna relación: ninguna operación borra en cadena.

### Indexes

| Table | Index | Why |
|---|---|---|
| `subjects` | `id`, `semester`, `status` | Cuadrícula por semestre y candidatos del recomendador |
| `items` | `id`, `subjectId`, `dueAt`, `[source+externalId]` | Filtro por materia, orden por fecha y upsert de sincronización |
| `grades` | `id`, `subjectId`, `[source+externalId]` | Notas por materia y upsert |
| `scheduleBlocks` | `id`, `subjectId`, `day`, `source` | Reemplazo del horario importado |
| `settings` | `key` | Lectura por clave |
| `syncRuns` | `id`, `source`, `startedAt` | Registro ordenado por fecha |
| `notified` | `key` | Deduplicación |

`hidden` y `done` no se indexan: IndexedDB no indexa booleanos; se filtran en memoria.

### Schema

```ts

  subjects: "id, semester, status",
  items: "id, subjectId, dueAt, [source+externalId]",
  grades: "id, subjectId, [source+externalId]",
  scheduleBlocks: "id, subjectId, day, source",
  settings: "key",
  syncRuns: "id, source, startedAt",
  notified: "key",

```

El archivo completo (`src/db/db.ts`) y los esquemas zod (`src/domain/schemas.ts`) están como
cuerpos literales en el paso 2 de §9.

### Migrations

Dexie versiona el esquema en código. `applySchema` declara `version(1).stores(SCHEMA_V1)`. Un
cambio futuro agrega `version(2).stores(...)` (y `.upgrade(...)` si mueve datos) **debajo** de la
versión 1, sin editarla. No hay comando de migración: Dexie la aplica al abrir la base. La prueba
`tests/db/migration.test.ts` demuestra que las filas escritas con la versión 1 sobreviven a una
versión posterior. Antes de un cambio de versión, el estudiante exporta un respaldo.

### Seed data

`src/data/pensum.seed.ts` (archivo `[W]`) exporta `PENSUM_SEED_TEXT`: una materia por línea con el
formato `semestre|estado|tipo|nombre|prerrequisitos`. Estado `A` = aprobada, `C` = cursando,
`P` = pendiente. Tipo `O` = obligatoria, `F` = profundizacion. Prerrequisitos separados por `;`
con el nombre exacto de otra línea. Los créditos se cargan como `null`.

`parsePensumSeed` (paso 4) lo convierte en filas de `subjects`, y el evento `populate` de Dexie
las inserta **solo al crear la base**. No hay comando de siembra. Los prerrequisitos son los que
registró el estudiante a partir de su propia malla, no una fuente oficial, y son editables.

## 5. API Design

No hay servidor ni rutas HTTP propias. La superficie de API de este proyecto son tres contratos:
los mensajes entre contextos de la extensión, la API REST de Classroom que se *consume*, y las
funciones de módulo que los pasos posteriores dan por hechas.

### Conventions

- Base path: NOT APPLICABLE — sin rutas HTTP propias. Base de la API consumida:
  `https://classroom.googleapis.com/v1`.
- Response envelope: `{ ok: true, data } | { ok: false, error: { code, message } }` en toda
  respuesta de mensaje y en toda función que puede fallar por datos de entrada.
- Error codes: `unknown_message` (mensaje que no cumple el contrato), `not_implemented` (tipo
  válido sin manejador registrado), `handler_error` (el manejador lanzó), `invalid_backup`
  (archivo de respaldo inválido), `auth_required` (no hay token válido de Classroom),
  `classroom_http_error` (Classroom respondió distinto de 200).
- Validation: zod. Esquemas de datos en `src/domain/schemas.ts`; contrato de mensajes en
  `src/sync/messages.ts`; respaldo en `src/domain/backup.ts`.
- Pagination: la de Classroom, por `pageToken` / `nextPageToken`; `listAll` sigue hasta agotarla.
- Idempotency: toda sincronización es un upsert por (`source`, `externalId`); repetirla no
  duplica filas.
- Rate limits: NOT APPLICABLE — un usuario que sincroniza a mano.

|---|---|---|---|---|

### Critical endpoints — full detail

**1. `sac/import`.** Carga: `SacCapture` =
`{ url: string, title: string, capturedAt: string, tables: { headers: string[], rows: string[][] }[] }`.
Validación: `sacCaptureSchema` (zod); las claves extra se descartan. Respuesta: `Result<SyncRun>`.
Efectos: una fila en `syncRuns` siempre; upsert en `grades`; reemplazo de los `scheduleBlocks` con
`source` `sac` solo si se reconoció al menos un bloque; actualización de `credits`, `status` y
`finalGrade` de materias respetando `overrides`; nombres sin asociar agregados a
`settings.unmatchedSubjects`. Casos de error: carga inválida → `unknown_message`; ninguna tabla
reconocida → `ok: true` con `SyncRun.status` `partial` y `error` `0 tablas reconocidas`, sin tocar
datos; excepción interna → `handler_error` y fila `syncRuns` con `status` `error`.

**2. Clasificación de tablas del SAC** (`classifyTable`). El encabezado se normaliza (minúsculas,
sin tildes, espacios colapsados) y se compara por **igualdad exacta** con los sinónimos de
`settings.headerSynonyms`; las columnas de nota parcial son las que cumplen la expresión
`partialGradePattern`. Tipos, en este orden de prioridad: `schedule` (materia + día + hora de
inicio), `grades` (materia + alguna columna de nota definitiva o parcial), `enrollment` (materia +
créditos), y si no, `unknown`.

**3. Motor de fusión** (`src/sync/merge.ts`):

| Función | Contrato |
|---|---|
| `upsertSynced(db, table, source, incoming)` | `table` es `items` o `grades`. Busca por `[source+externalId]`. No existe → crea con `overrides: []`, `hidden: false` (`created`). Existe con `hidden: true` → no la toca (`skipped`). Existe → copia cada campo entrante que no esté en `overrides`; si algo cambió, `updated`; si no, `skipped`. Nunca borra filas ausentes del lote. Devuelve `SyncCounts` |
| `editRecord(db, table, id, patch)` | Aplica el cambio validado. Si `source` no es `manual`, agrega cada clave cambiada a `overrides` |
| `removeRecord(db, table, id)` | `manual` → borra la fila. Otro `source` → `hidden: true` |
| `patchSubject(db, id, patch, origin)` | `origin` `student` → aplica y agrega las claves a `overrides`. `origin` `sync` → omite las claves que están en `overrides` |
| `runSync(db, source, work)` | Ejecuta `work`, escribe la fila de `syncRuns` (`ok`; `partial` si `unmatched` > 0 o si `work` devuelve una nota de error; `error` si lanza) y la devuelve. Nunca relanza |

**4. Sincronización de Classroom** (`syncClassroom`). Token por `browser.identity.launchWebAuthFlow`
(flujo implícito, `response_type=token`, redirección `browser.identity.getRedirectURL()`), guardado
con su vencimiento en `browser.storage.session`. Alcances, todos de solo lectura:
`classroom.courses.readonly`, `classroom.coursework.me.readonly`,
`classroom.student-submissions.me.readonly`, `classroom.courseworkmaterials.readonly`,
`classroom.announcements.readonly` (cada uno con el prefijo `https://www.googleapis.com/auth/`).
Mapeo: `courseWork` → ítem (`externalId` `cw|<courseId>|<id>`; `dueAt` =
`new Date(Date.UTC(año, mes - 1, día, horas, minutos)).toISOString()`, donde sin `dueDate` el
resultado es `null`, sin `dueTime` la hora es 23:59, y con `dueTime` cada campo ausente vale 0);
tipo por título y descripción: contiene
`parcial` o `examen` → `parcial`; contiene `quiz` → `quiz`; si no, `tarea`. Entrega con
`assignedGrade ?? draftGrade` y `maxPoints` > 0 → nota (`externalId` `sub|<courseId>|<courseWorkId>`,
`score` y `maxScore` en su escala original). Material cuyo título o adjunto cumple
`/acta|concertaci[oó]n/i` → ítem tipo `otro` con `isActa: true` (`externalId`
`mat|<courseId>|<id>`); los demás materiales se ignoran. Curso ↔ materia: igualdad de nombre
normalizado y después `settings.subjectAliases`; sin coincidencia → `unmatchedSubjects`. Errores:
sin token → `auth_required`; respuesta distinta de 200 → `classroom_http_error`, y con 401 además
se borra el token. Ningún error borra datos.

## 9. BUILD ORDER

### Reglas de un paso

1. Un paso se termina en una sentada: máximo 5 archivos y entre 2 y 6 criterios.
2. Cada paso tiene `Do`, `Done when`, `Verify` y `Checkpoint`, y se ejecutan en ese orden.
3. Antes de `Verify`, el constructor ejecuta `pnpm format` (arreglos seguros de Biome).
4. `Verify` es shell literal y se ejecuta desde la raíz del proyecto. Cada línea sale con 0 cuando
   el paso está correcto. `pnpm build` va antes de `pnpm typecheck` porque regenera `.wxt/`.
5. Un paso no está hecho hasta que pasan sus comandos **y** los de los pasos anteriores (`pnpm
   test` y `pnpm e2e` corren la suite completa acumulada).
6. `Checkpoint` hace commit y etiqueta. Si un paso sale mal: `git reset --hard` a la etiqueta del
   paso anterior y se reintenta.
7. No se salta ningún paso. Si uno se bloquea, se detiene y se reporta.
8. Ningún paso edita un archivo `[W]` de §3, salvo `entrypoints/background.ts` donde se indica.

16 pasos = 16 tareas en `tasks.json` = 16 bloques de tarea repartidos en 3 épicas:

```ts
export const DB_NAME = "uniplan";

  subjects: "id, semester, status",
  items: "id, subjectId, dueAt, [source+externalId]",
  grades: "id, subjectId, [source+externalId]",
  scheduleBlocks: "id, subjectId, day, source",
  settings: "key",
  syncRuns: "id, source, startedAt",
  notified: "key",
} as const;

export type TableName = keyof typeof SCHEMA_V1;

export const TABLE_NAMES = Object.keys(SCHEMA_V1) as TableName[];

export type UniplanDb = Dexie & {
  subjects: Table<Subject, string>;
  items: Table<Item, string>;
  grades: Table<Grade, string>;
  scheduleBlocks: Table<ScheduleBlock, string>;
  settings: Table<SettingRow, string>;
  syncRuns: Table<SyncRun, string>;
  notified: Table<NotifiedRow, string>;
};

export function applySchema(target: Dexie): void {
  target.version(1).stores(SCHEMA_V1);
}

export function createDb(name: string = DB_NAME): UniplanDb {
  const instance = new Dexie(name) as UniplanDb;
  applySchema(instance);
  return instance;
}
```

```ts
function nowIso(): string {

export async function getSetting<K extends keyof Settings>(
  db: UniplanDb,
  key: K,
): Promise<Settings[K]> {
  const row = await db.settings.get(key);
  if (row === undefined) {
    return DEFAULT_SETTINGS[key];
  }
  return row.value as Settings[K];
}

export async function setSetting<K extends keyof Settings>(
  db: UniplanDb,
  key: K,
  value: Settings[K],
): Promise<void> {
  await db.settings.put({ key, value });
}

export async function putSubject(
  db: UniplanDb,
  subject: Subject,
): Promise<void> {
  await db.subjects.put(subjectSchema.parse(subject));
}

export type NewItemInput = {
  title: string;
  type?: ItemType;
  subjectId?: string | null;
  dueAt?: string | null;
  weightPct?: number | null;
  notes?: string;
};

export async function addManualItem(
  db: UniplanDb,
  input: NewItemInput,
): Promise<Item> {
  const now = nowIso();
  const item = itemSchema.parse({
    id: crypto.randomUUID(),
    type: input.type ?? "tarea",
    title: input.title.trim(),
    subjectId: input.subjectId ?? null,
    dueAt: input.dueAt ?? null,
    weightPct: input.weightPct ?? null,
    notes: input.notes ?? "",
    done: false,
    links: [],
    isActa: false,
    source: "manual",
    externalId: null,
    overrides: [],
    hidden: false,
    createdAt: now,
    updatedAt: now,
  });
  await db.items.add(item);
  return item;
}

export async function listVisibleItems(db: UniplanDb): Promise<Item[]> {
  return db.items.filter((item) => !item.hidden).toArray();
}

export type NewGradeInput = {
  subjectId: string;
  label: string;
  score: number;
  maxScore: number;
  weightPct?: number | null;
};

export async function addManualGrade(
  db: UniplanDb,

): Promise<Grade> {

    maxScore: input.maxScore,
    weightPct: input.weightPct ?? null,
    source: "manual",
    externalId: null,
    overrides: [],
    hidden: false,
    updatedAt: nowIso(),
  });
  await db.grades.add(grade);
  return grade;
}
```

### Bootstrap

Se ejecuta desde la raíz del proyecto, con el bundle ya en `blueprints/uniplan-uq/`. Es seguro
ejecutarlo dos veces. No arranca ningún servidor ni siembra nada: no hay servidor, y la base se
siembra sola en el navegador la primera vez que se abre el panel.

```bash
# order matters: repo init → workspace copy (lands .gitignore, .gitattributes, biome.json and
# package.json before anything is installed, linted or committed) → install → browser binary →
# lint → first commit
test -d .git || git init -b main
# ^ idempotent; checks this directory itself, so an enclosing repository is never reused
cp -Rn blueprints/uniplan-uq/workspace/. . || true
# ^ -n: never clobber a file the build has since changed (package.json, entrypoints/background.ts,
#   every config). GNU cp exits 0 when it skips; BSD cp exits 1, and skipping is the intended
#   outcome, hence "|| true". rsync is not available in Git Bash.
pnpm install
# ^ reads the copied package.json; postinstall runs "wxt prepare" and generates .wxt/
pnpm exec playwright install chromium
# ^ browser binary for the e2e gates; do not add --with-deps on Windows
pnpm lint
# ^ must exit 0 with the bundle present: biome.json force-ignores blueprints/
git add -A && (git diff --cached --quiet || git commit -m "chore: bootstrap")
# ^ first run: creates the first commit, with .gitignore already in place. Re-run with nothing
#   new staged: skips the commit and exits 0.
```

Archivos que la copia nunca sobrescribe una vez existen: todos, y en particular `package.json`,
`pnpm-lock.yaml`, `entrypoints/background.ts` y las configuraciones.

El repositorio lo crea este bloque, no un scaffolder: este proyecto no usa ninguno. El manifiesto
`package.json` lo entrega el blueprint completo, con todas las dependencias fijadas.

## 14. Security & Secrets

| Concern | Control | Implemented in |
|---|---|---|

| Output encoding / XSS | React escapa todo el texto; prohibido `dangerouslySetInnerHTML`; el content script crea nodos con `textContent` | `src/ui/**`, `entrypoints/sac.content.ts` |
| SQL injection | NOT APPLICABLE — sin SQL; IndexedDB por clave | no aplica |
| AuthN / AuthZ | NOT APPLICABLE — sin cuentas propias; la extensión nunca ve credenciales | no aplica |
| CSRF | NOT APPLICABLE — sin servidor | no aplica |
| Rate limiting / abuse | NOT APPLICABLE — un usuario, sincronización manual | no aplica |
| Webhook verification | NOT APPLICABLE — sin webhooks | no aplica |
| Dependency audit | `pnpm audit` antes de actualizar dependencias; lo corre el estudiante | manual |
| Security headers | CSP por defecto de Manifest V3 (sin `eval`, sin código remoto); no se relaja | `wxt.config.ts` no declara `content_security_policy` |
| PII handling | Nombres de materias, notas y fechas del estudiante, solo en IndexedDB local. Se borran al quitar la extensión; el respaldo JSON es un archivo en claro que el estudiante custodia | `src/db/db.ts`, `src/domain/backup.ts` |
| Logging hygiene | No se registran tokens ni contenido de páginas; `syncRuns` guarda conteos y un mensaje de error | `src/sync/merge.ts` |
| Permisos mínimos | Conjunto fijo, justificado y vigilado por una prueba | `wxt.config.ts`, `PERMISSIONS.md`, `e2e/smoke.spec.ts` |

**Hard rules**

- La extensión nunca guarda, escribe ni automatiza credenciales, y nunca automatiza el inicio de
  sesión del SAC.
- La integración con el SAC es de solo lectura: nunca hace clic, envía, navega ni matricula.
- Nada sale del equipo salvo las llamadas a `classroom.googleapis.com` y al consentimiento OAuth
  de Google. `src/sync/classroom-client.ts` es el único archivo con `fetch`, y un `grep` lo vigila.
- El ID de cliente de Google no es un secreto y aun así no se incluye en el build: lo escribe el
  estudiante.
- Las reglas `deny` de `.claude/settings.json` desaniman; no son aislamiento. Este proyecto no
  tiene secretos que lo requieran.

El proyecto no maneja datos regulados: son datos académicos propios de un único usuario que no
salen de su equipo. Si los alcances de Classroom se clasifican como sensibles o restringidos está
**sin verificar**; se comprueba en la lista de lanzamiento.

## 15. Accessibility

**Target: WCAG 2.2 Level AA** en el panel. Es una herramienta de un solo usuario, pero el teclado
y el contraste son parte del diseño decidido y sus criterios están en los pasos de §9.

| Requirement | Rule |
|---|---|
| Semantic HTML | `nav` y `main`; un solo `h1` (`Uniplan UQ`); `h2` por sección y grupo; listas como listas |
| Keyboard | Todo control es alcanzable y operable con teclado; orden lógico; sin trampas. Las tarjetas del pensum son botones |

| Color | El estado nunca se comunica solo con color |

| SC | Requirement |
|---|---|
| 2.4.11 Focus Not Obscured (Min) | No hay cabeceras ni avisos fijos que tapen el foco; el panel lateral del pensum no cubre la tarjeta enfocada |

| 2.5.8 Target Size (Min) | Todo objetivo de puntero mide al menos 24×24 px |

### 20.1 Global acceptance gate

El proyecto está **terminado** cuando cada comando sale con 0 sobre un checkout limpio:

```bash
pnpm install --frozen-lockfile                  # expect: exit 0
pnpm exec playwright install chromium           # expect: exit 0
pnpm build                                      # expect: exit 0
pnpm typecheck                                  # expect: exit 0, cero errores
pnpm lint                                       # expect: exit 0, cero errores
pnpm test                                       # expect: exit 0, 0 failed, 0 skipped
pnpm e2e                                        # expect: exit 0, 0 failed — EJECUTA la extensión construida

                                                #         la verificación de accesibilidad por teclado de §15
status=0; grep -rnE '\.(skip|only)\(' tests e2e || status=$?; test "$status" -eq 1
                                                # expect: exit 0 — 1 = ninguna prueba omitida ni enfocada
status=0; grep -rnE 'runtime\.(sendMessage|onMessage)' entrypoints src --exclude=messages.ts || status=$?; test "$status" -eq 1

status=0; grep -nE '\.(click|submit)\(|location\.(href|assign|replace)|window\.open|fetch\(|XMLHttpRequest' entrypoints/sac.content.ts src/sync/sac-extract.ts || status=$?; test "$status" -eq 1
```

Cada expectativa es una propiedad, no un conteo. Las cuatro líneas de `grep` afirman el código 1
